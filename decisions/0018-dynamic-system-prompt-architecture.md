# 0018. Dynamic System Prompt Architecture with LM-XML

Date: 2026-11-01

## Status

Accepted

## Context

Prior to this decision, Seamus provided only a rudimentary, flat-text system prompt generated by `build_sandbox_system_prompt` in `src/seamus/harness/sandbox.py`. This prompt was static at agent instantiation time and covered only basic filesystem boundaries (informing the agent that `/workspace` is mounted and persistent while other paths are transient).

To function effectively as a high-discipline, autonomous software engineering agent across varied LLMs (OpenAI, Anthropic, Gemini, DeepSeek, open-weights), Seamus requires:
1. **Predictable, Structured Prompting**: Large language models adhere significantly better to structured XML tags than flat prose. The format must be human-readable, deterministic, and natively serialize complex and nested data without arbitrary formatting choices or fragile escaping.
2. **Per-Inference Dynamic Generation**: System prompt instructions must be re-evaluated dynamically per model inference turn rather than fixed once during graph compilation. This allows runtime variables (current timestamp, session/agent identifiers, turn progression, and future modes/personas) to adapt without requiring agent graph re-compilation.
3. **Rigorous Engineering Discipline**: A comprehensive set of guidelines inspired by industry-leading harnesses (Cursor, Claude Code, and Antigravity IDE), covering surgical minimal diffs, code comment policies (explain why, never what), verification before completion, and tool invocation discipline.

## Decision

1. **Adopt LM-XML Serialization**:
   - Integrate [`lmxml`](https://github.com/filipmalczak/lmxml) as a core runtime dependency.
   - Define structured Pydantic models for system prompt documents (`OperatingEnvironment`, `DynamicContext`, `SystemPromptDocument`) and serialize them via `lmxml.dumps()`.
   - Ensure clean tag emission without empty/None noise by filtering `None` attributes prior to serialization.

2. **Per-Inference Dynamic Prompt Middleware**:
   - Introduce `DynamicSystemPromptMiddleware` subclassing `AgentMiddleware` from `langchain.agents.middleware`.
   - Wrap both synchronous (`wrap_model_call`) and asynchronous (`awrap_model_call`) model invocations, overriding `request.system_message` with a freshly generated LM-XML prompt string from `SessionAgentRunner.build_effective_system_prompt()`.
   - Maintain the static base scaffold as `system_prompt` on `create_deep_agent` to ensure proper fallback and inspection compatibility.

3. **Core Coding Agent Persona & Discipline**:
   - Establish Seamus's identity as an autonomous AI software engineering agent with high autonomy, rigorous discipline, and surgical precision.
   - Enforce explicit boundaries: `/workspace` is version-controlled and persistent; paths outside are transient and discarded on sandbox restart.
   - Mandate investigation before editing, surgical diffs, no commentary comments, test/linter verification before task completion, and dedicated tools over raw shell execution.
   - Format user-configured custom instructions within a dedicated `<custom_instructions>` XML tag when present.

4. **Inspector Integration**:
   - Update `seamus.harness.inspector` to decompose system prompts into the structured LM-XML scaffold, user-defined custom prompt, and the full dynamic composite prompt.

## Consequences

### Positive

- System prompts are predictable, unambiguous, and cleanly formatted for all model families.
- The prompt is dynamic per inference, allowing timestamp, session context, and future mode/persona changes without rebuilding the LangGraph graph.
- Engineering discipline rules align Seamus's autonomous behavior with modern software engineering standards.
- Full backward compatibility is preserved for existing inspection APIs and sandbox settings.

### Negative / Trade-offs

- Introduces a dependency on `lmxml`.
- Middleware dynamic interception adds negligible runtime overhead per model call to serialize prompt structures.
