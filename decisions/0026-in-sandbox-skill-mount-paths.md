# 0026. In-Sandbox Skill Mount Paths and Comprehensive Precedence Model

Date: 2026-11-03

## Status

Accepted

## Context

In [0024-anthropic-skills-and-system-settings.md](./0024-anthropic-skills-and-system-settings.md), system-wide skill directories were introduced and mounted directly using host filesystem paths (`mountPath=str(skill_path)`). Furthermore, `SessionAgentRunner` passed these host paths directly to LangChain DeepAgents `create_deep_agent(skills=...)`.

This led to two critical issues:
1. **Host Path Leakage into Sandboxed System Prompts**: The LLM's system prompt generated by `SkillsMiddleware` displayed host filesystem paths (e.g. `/home/user/.seamus/skills`), instructing the sandboxed agent to read skills from host locations that did not conform to the sandbox container's internal filesystem structure.
2. **Ambiguous Precedence Hierarchy**: The initial integration ordered system skills ahead of session skills, but lacked explicit collision rules for multiple system directories and did not account for upcoming project/auxiliary repository mounts or non-overridable bundled platform skills.

## Decision

1. **In-Sandbox Mount Path Contract (`/skills/system/{idx}`)**:
   - In `SeamusOpenSandboxBackend.build_skill_volumes()`, each system skill directory configured in `SystemSettings.skill_directories` is mounted at `/skills/system/{idx}`, where `idx` is its 0-based position in `SystemSettings.skill_directories`:
     `Volume(name=f"skill-{idx}", mountPath=f"/skills/system/{idx}", readOnly=True, host=Host(path=str(skill_path)))`
   - Non-existent directories on the host continue to be cleanly and silently skipped, preserving the original index mapping for existing directories.
   - All external skill mounts reside strictly under the `/skills/` namespace inside the container.

2. **Dual Support for `skills` and `.skills`**:
   - Workspace directories (and future project/auxiliary mounts) support both visible `skills` and hidden `.skills` subdirectories.
   - Visible `skills` take precedence over hidden `.skills` because dotted directories are hidden and serve as background defaults, whereas non-dotted directories represent explicit, prominent overrides.
   - `WorkspaceManager.create_session_workspace()` automatically initializes both `data/skills` and `data/.skills`.

3. **Comprehensive Skill Precedence Model**:
   The full precedence hierarchy from highest to lowest priority is:
   1. *(future)* `/skills/bundled`: Top-most priority once introduced; integral Seamus platform skills (such as `a2ui`) that are immutable and non-overridable.
   2. `/workspace/skills`: Top session priority; explicit session-specific workspace skills.
   3. `/workspace/.skills`: Session background/default skills.
   4. *(future)* `/projects/<first>/skills`: Explicit project-level skills for primary auxiliary repository.
   5. *(future)* `/projects/<first>/.skills`: Project background skills for primary auxiliary repository.
   6. *(future)* `/projects/<second>/skills`: Secondary auxiliary project skills...
   7. *(future)* `/projects/<second>/.skills`: Secondary auxiliary project background skills...
   8. `system[0]`: Highest priority system-wide default (mounted at `/skills/system/0`).
   9. `system[1]`: Mounted at `/skills/system/1`.
   ...
   N. `system[last]`: Lowest priority system-wide fallback (mounted at `/skills/system/{last}`).

4. **DeepAgents Reverse Ordering ("Last One Wins")**:
   - DeepAgents `SkillsMiddleware` resolves name collisions by loading sources sequentially, where later sources in the list override earlier ones ("last one wins").
   - `SeamusOpenSandboxBackend.get_skill_sources()` reverses the system skill list so that `system[last]` is loaded first, followed by `system[1]`, `system[0]`, `/workspace/.skills`, and finally `/workspace/skills`.
   - `SessionAgentRunner` supplies these in-sandbox sources directly to `create_deep_agent(skills=...)`.

## Consequences

### Positive
- Strict sandbox isolation: Sandboxed agents see only in-sandbox paths (`/skills/system/{idx}` and `/workspace/...`), with zero host path leakage into prompts or tool executions.
- Clean namespacing: Leaves `/skills/bundled` reserved and isolated for incoming bundled Seamus skills (e.g. `a2ui`).
- Predictable precedence: Distinct layering between session workspace skills, project mounts, and ambient system defaults.
- Dual-directory flexibility: Allows agents and users to place background skills in `.skills` and prominent overrides in `skills`.

### Negative / Trade-offs
- Multiple system skill directories produce multiple numbered volume mounts (`/skills/system/0`, `/skills/system/1`), requiring developers inspect system settings indices to trace specific host source directories.
