# Conventions

Project-specific implementation, tooling, and development conventions not fully enforced by tooling.

## Python Standards
- Python 3.12+ language features (e.g., standard generic type annotations, pattern matching where appropriate).
- Avoid suppression of linter (`# noqa`) or type-checker (`# type: ignore`) warnings without explicit, documented rationale.
- Line length: 100 characters (enforced by `ruff`).

## REST API Conventions
- Base path prefix is `/api/v-alpha/`.
- Paths accept both UUID strings and slug names for identifiers `<A>`, `<S>`, and `<T>`.
- Slugs match `^[a-z0-9]+(?:-[a-z0-9]+)*$` and are unique within their parent scope.
- Updates are performed via `POST` sending the full updated object to the entity route (`POST .../config-template`, `POST .../agent/<A>`, `POST .../session/<S>`, `POST .../thread/<T>`). Passing `null` explicitly clears optional fields.
- No `DELETE` endpoints exist anywhere in the API.
- User chat input is dispatched via `POST .../session/<S>/input`. If the session agent is not in the `AWAITING_USER` state, return HTTP 409 Conflict.
- Session thread shortcut `GET .../session/<S>/thread` redirects with `307 Temporary Redirect` to the active open thread `.../thread/<T_open>`.
- Thread message streaming `GET .../thread/<T>` uses `text/event-stream` (SSE), first replaying past events from memory and then streaming live AG-UI events.

## Frontend & UI Conventions
- Single-page application housed under `ui/` using React 19, TypeScript, and Vite.
- All backend communication routed through `/api/v-alpha/` and `/health`.
- Tree hierarchy reflects Agent $\to$ Session $\to$ Thread containment.
- In-browser JSON config editor provides raw JSON inspection and modification, formatting, and syntax validation before sending full-object updates.
- Real-time event consumption uses standard SSE, gracefully handling past event replay and live event broadcast.

## Container Orchestration & Launch Conventions
- Docker Compose defines `backend` (FastAPI), `frontend` (Nginx), `opensandbox` (local OpenSandbox lifecycle server with `/var/run/docker.sock` mounted), `gitea` (Git persistence service on port 3001), `postgres` (intermediate database backing Gitea and OpenBao), `openbao` (KV v2 secrets vault), and `ollama` (local model provider in CPU mode).
- `./run.sh` provides 1-click startup and opens UI in the default browser.
- `./run.sh --restart` (`-r`) rebuilds application container images (`opensandbox`, `backend`, `frontend`) and recreates running application containers to apply code updates while preserving infrastructure containers (`postgres`, `gitea`) and persistent data volumes (`gitea-data`, `postgres-data`, `seamus-workspaces`).
- `./run.sh --clean` (`-c`) stops all services, removes all persistent volumes and data storages, and restarts all services with clean data.
- OpenSandbox API authentication is autogenerated and managed internally by the runtime (`/var/run/seamus-opensandbox/api_key` or `.seamus/opensandbox/api_key`) and must never be exposed in `.env.template` or user-facing APIs.

## Git and Workflow Conventions
- Feature branches formatted as `NNNN-short-task-description` branched from `master`.
- Numbering checked against decisions and local/remote branches.
- Commits require explicit user instruction or authorization in approved plan.
- All production and `./knowledge/` modifications staged prior to review.
- In agent repositories, commits are strictly partitioned by prefix: `config:` for agent/session configuration updates on `agent/config/**`, `checkpoint:` for automated checkpoint workspace commits on `data/` and `agent/state/**`, and `state:` for turn-completion thread event updates.

## Testing Conventions
- Pytest test files named `test_*.py` located under `tests/`.
- Test observable behaviors and edge cases rather than private implementation details.
- Avoid external network calls during unit and integration test runs by using test doubles or mock run providers.
- Test suite execution uses an ephemeral, dedicated Gitea container (`tests/conftest.py`) with SQLite and dynamic port assignment (`127.0.0.1::3000`), completely shielding the live development stack (`http://localhost:3001`, `.seamus/workspaces`) from test pollution and permitting parallel test runs.
- Logfire test assertions use `TestExporter` and `SimpleSpanProcessor` with `send_to_logfire=False`.
- Frontend builds verified with `npm run build` in `ui/`.
- End-to-end tests live under `tests/e2e/` and drive the real harness stack over the public HTTP API. Only two substitutions are permitted: the live inference provider (replaced by the `steerable` scripted provider) and the OpenSandbox container (replaced by the in-process host-filesystem stub in `tests/e2e/stub_sandbox.py`). No API key, network access, or live container may be required.
- End-to-end tests are organised around user-observable behaviour (conversation streaming, plan and artifact lifecycles, session termination, branching, mode switching, thread acceptance, Sync PR lifecycle, inspector reporting, telemetry span hierarchy), not around line coverage.
- A specified-but-unimplemented behaviour is recorded as a non-strict `xfail` test whose reason names the backlog entry tracking it. Existing tests are never weakened or removed to accommodate a gap.
- Frontend component tests live under `ui/tests/` and run on Node's native test runner (`npm test`). They load real production components from `ui/src` (bundled with esbuild) and assert on rendered output, so a test can never drift from the implementation.

## Continuous Integration Conventions
- Automated CI pipeline maintained under `.github/workflows/ci.yml`.
- Triggers on `push` and `pull_request` across all branches with `concurrency` cancellation of prior in-flight runs (`cancel-in-progress: true`).
- `lint-and-typecheck` job runs on `ubuntu-latest` verifying backend formatting (`uv run ruff format --check`), linting (`uv run ruff check`), and type checking (`uv run mypy`) against frozen lockfiles (`uv sync --frozen`).
- `frontend` job runs on `ubuntu-latest` executing `npm ci` and `npm run build` (`tsc -b && vite build`) in `ui/`.
- `test-docker` job executes the full test suite on `ubuntu-latest` using the ephemeral Gitea container persistence fixture.
- `test-in-memory` job executes the test suite on `ubuntu-latest` in parallel with `SEAMUS_TEST_IN_MEMORY=true` (disabling Docker persistence) to guarantee fast feedback and verify pure in-memory execution isolation.
- `test-e2e` job executes `uv run pytest tests/e2e` on `ubuntu-latest` with `SEAMUS_TEST_IN_MEMORY=true`. The suite needs neither an API key nor a live container, so it runs in seconds on every push.
- The `frontend` job additionally runs `npm test` (Node native test runner) after `npm run build`.
- Cross-platform macOS and Windows runner support is deferred and tracked as technical debt.
- Package publishing and deployment stages are omitted.

## Telemetry & Tracing Conventions
- Use `f"agent {agent_identifier}"`, `f"session {session_identifier}"`, and `f"thread {thread_identifier}"` for span naming so spans are immediately distinguishable in traces.
- Spans must include entity IDs, names, and operational attributes (`agent_id`, `session_id`, `thread_id`, `model`, `run_id`).
- Standard logfire scrubbing callback must preserve Seamus domain `session` attributes while redacting secrets.
